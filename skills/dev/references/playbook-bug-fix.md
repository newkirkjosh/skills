# Bug fix

**Write scope:** read-only reproduction and diagnosis first; after the Scope Brief confirmation, a `fix/` worktree and small `fix-` change folder, then the shared lifecycle's authorized writes. No issue creation in this front end and no merge.

1. Read `scope-brief.md`, build the brief from the user's own words with `Playbook: bug-fix`, and show that choice, Path with reason, Interpreted scope, Also update and Explicitly out of scope. Preserve any named existing issue for Phase 1. This playbook is only for new work; existing state uses pickup.
2. Reproduce the observed wrong behavior on the real surface through read-only actions, then establish the root cause before creating a worktree. Record observed versus expected behavior and the reproduction evidence. Reproduction grants no permission for hardware, root or live-service writes: follow the shared real-device permission rule; an uncertain side effect stops for authorization. If reproduction or root cause cannot be established, report the missing evidence and stop before creating artifacts.
3. If the root cause needs architectural work (a component interface or how components fit together), stop this front end before creating the worktree. Retain the brief context, select `Playbook: change`, and read `playbook-change.md`; its architectural design approval applies before Phase 1.
4. For a bounded fix, create `fix/<name>` with `wt switch --create <branch> --no-cd`, locate its path as in Worktrees in `../SKILL.md`, and work there. Write `openspec/changes/fix-<name>/scope-brief.md` with `Playbook: bug-fix`, `proposal.md`, `specs/stories.md` (observed versus expected behavior and a regression-guard story), a short `design.md` and one-layer `tasks.md` covering the fix and every Also update item. Use the spec-writer skill's artifact formats; do not start its architectural front end for a bounded fix.
5. Commit the change folder (`docs(openspec): …`). Do not file an issue or write `issues.md` here. Read `lifecycle.md` and run it from its top: the no-issues row takes Phase 1, which reuses a named issue or files one and writes the mapping.
