# PR evidence contract

The read-only helpers in this skill's `scripts/` port the catalog's former GitHub head-status/CI/CodeRabbit helper concepts. They retain no upstream material beyond the existing dev attribution and license. JSON validation and paginated connection traversal live in the standard-library Python helper; shell wrappers need bash, Python 3 and gh, with no package installation.

Resolve the catalog from the loaded skill's real symlink target. For dev, `<dev-dir>` is that directory; for ship, resolve its real directory and use its sibling `../dev`. Never resolve relative to the project's working directory.

- `bash <dev-dir>/scripts/pr-status.sh <pr-number> <owner/repo>` emits JSON evidence, not merge permission. Exit 0 means complete collection for the pinned head; 5 means API rate limit, 6 means head moved, 8 means read failure, 2 means usage error. All errors invalidate evidence. Any subsequent push invalidates the report.
- `bash <dev-dir>/scripts/wait-for-ci.sh <pr-number> <owner/repo> [whole-minutes]` waits for Actions runs on the pinned head. PASS means those runs succeeded, not that branch-required checks or external statuses are satisfied. Required contexts and configured reviewers must be established from repository authority and compared against the report by the caller.
- `bash <dev-dir>/scripts/wait-for-coderabbit.sh <pr-number> <owner/repo> [whole-minutes]` waits for the CodeRabbit check. Success does not interpret review prose. `WAIT_AFTER_RUN=<id>` treats the indicated skipped run as pending until it changes; a later skip is PAUSED again.

Wait exits: 0 PASS, 1 FAIL (including skipped CI), 2 invalid input, 3 TIMEOUT/pending or absent review, 4 NO_RUNS (CI only), 5 rate-limit evidence/API limit, 6 HEAD_MOVED, 7 PAUSED (CodeRabbit only), 8 READ_ERROR. JSON `state` identifies the exact result. `WAIT_INTERVAL` is a nonnegative whole number of seconds (default 30); default deadline is 20 minutes, shared by collection, pagination and individual API calls. Expiry during a read returns TIMEOUT with unknown sources; a zero-minute wait performs no reads. No helper posts comments or nudges review. Native host monitoring/wait rules override these fallback invocations.

An absent check is UNKNOWN, never NOT_CONFIGURED. Positive not-configured evidence must come from repository/service authority, be recorded with its source and treated as optional only if repository policy permits. Missing, stale, pending, skipped, paused or unreadable required evidence blocks merging. Rate-limit comments are considered only while review is pending, and only when updated (falling back to creation time) at or after both the head commit and the latest force-push. Completed review is not overridden by old rate-limit prose.

All REST collections paginate until a short page; counted collections must match total_count. Threads paginate with cursors and totalCount. Review comments are separately fully paginated so thread bodies are not truncated by nested connection limits. Reviews include bodies and commit IDs; old reviews are retained separately. Source errors are unknown, never empty collections. The head is reread after collection and immediately before waiter evidence verdicts while budget remains. Deadline expiry performs no final API read and returns TIMEOUT with unknown sources; a check completing after the last observation is not yet verified. Relaunch within the caller’s remaining overall budget to collect fresh evidence.

Caller merge gates: complete report on the candidate SHA; all required checks successful; each configured reviewer completed on that SHA; every review body and comment triaged; every unresolved thread accounted for and resolved where authorized; independent local verification/cross-review requirements met; repository policy grants merge authority and excludes none of the touched files. Explicit optional not-configured evidence can exempt only that optional reviewer. A report with zero threads still requires body-only finding triage. Recollect immediately before squash merge, and use `gh pr merge <pr> --squash --delete-branch --match-head-commit <sha>`. The helper never merges.

Before collecting merge evidence, construct and verify the policy below; UNKNOWN coverage blocks merging. Set `PR_EVIDENCE_POLICY` to a caller-prepared JSON file with `source` (repository authority citation), `required_checks` (check/context names), `required_reviewers` (login names), and optional `optional_not_configured` (reviewer-to-positive-evidence strings). Missing policy yields UNKNOWN coverage. The helper reports each required check/reviewer’s observed state; it never approves prose or validates the authority citation. Optional exemptions cannot overlap required reviewers. The caller must verify this file against repository rules; it is no authority of its own.

CI allows three minutes for the first run to appear; an earlier invocation deadline returns TIMEOUT, not NO_RUNS. NO_RUNS is never CI green. Required check coverage includes every returned check with its app and the latest status per producer; all matches must succeed. The caller must also verify the app/producer identity against repository authority; a same-named check from another app cannot stand in for the configured check. Review history across all commits determines whether CHANGES_REQUESTED remains outstanding; COMMENTED never clears it. A later approval or dismissal clears the objection, but a review on an older commit alone never satisfies head coverage. Thread `first_comment_id` maps to the fully paginated REST review comments.
