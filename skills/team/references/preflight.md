# Preflight

Run before taking anything into scope, after the run lock (`run-state.md`). Any failure: say which check failed and stop, before starting any change.

## Host capabilities

- **Not interactive** (`claude -p`, `codex exec`, a scheduled job; see Headless sessions in `dev`'s host-adapters reference): fail here, before anything below. `team` v1 needs a session the host can wake, and ending a turn in one of these ends the session.
- **Claude Code:** background subagents, a completion notification when one finishes, its output file (to read progress), `TaskStop`, `SendMessage`, and a heartbeat that wakes an ended turn, since supervision depends on it. Check this first, before any probe: start one background `Bash` command, `sleep 60` with the heartbeat's `timeout: 600000`, then **end the turn**, telling the user that preflight is waiting for that wake, and that if nothing has happened after five minutes they should send any message, which cancels the run and releases the lock. Preflight continues only when the command's completion notification starts the next turn. If a user message starts it instead, the wake is unproven: **Stop** the command and fail preflight.
- **Codex:** `spawn_agent`, `wait_agent`, `followup_task`, and a verifiable stop/status path from dev’s host adapter. Current backends supply `interrupt_agent` and `list_agents`; a legacy backend may supply `close_agent`. Absence of `close_agent` alone is not a failure. Prove nested delegation, continuation, stopping and capacity reuse with the probe below; record which lifecycle was verified. When `close_agent` is supplied but `interrupt_agent` is absent, select the legacy close path from the first probe: require explicit close confirmation after each completed role before starting its successor, so capacity is tested without first exhausting it. No live output read is needed.

## Permissions, through the real delegation path

The session's permission mode must not prompt for `dev`'s normal work, and its sandbox must actually allow it. An immediate permission rejection also fails preflight; it is not a waiting prompt. Preserve the operation and actual denial reason, stop the probe through the existing cleanup rules, and report the failure without a 30-minute wait, retry or permission workaround (dev's host adapter, Background permission results). Prove access the way the run will use it:

1. Spawn a disposable **probe coordinator** exactly as a `dev` worker would be started (Session operations in `SKILL.md`). It checks, without changing anything outside a scratch branch:
   - after step 2 returns the scratch worktree's path, `git push --dry-run origin HEAD:refs/heads/team-probe-<random>` from it, then deletes exactly the files the role reported, removes that worktree and its branch without forcing, and confirms all of it is gone;
   - before that cleanup, that a commit signs without a prompt, when the repository signs commits (`git config --get commit.gpgsign` prints `true`, or a branch rule requires signatures): in the scratch worktree, `git commit-tree -S "HEAD^{tree}" -p HEAD -m team-probe` must print a SHA whose `git cat-file commit <sha>` has a `gpgsig` header (`-S` is required: `commit-tree` ignores `commit.gpgsign`). It writes an unreferenced commit object and moves no branch, so the cleanup's non-forced branch delete still works. A locked signing agent fails here instead of on `dev`'s first commit, after a change has started;
   - `gh pr list --limit 1` and `gh api repos/<owner>/<repo> --jq .permissions.push` (must print `true`);
   - a read of the tracker the repository's `AGENTS.md` names (change folders may not have an `issues.md` yet);
   - that `cross-review`'s script is present and parses (`bash -n`), and the other model's CLI starts (`codex --version` or `claude --version`).
2. The probe coordinator spawns one **probe role** the way `dev` spawns its roles. The role creates a scratch worktree at the real worktrunk destination (`wt switch --create team-probe-<random> --no-cd`), writes a file in it and in the scratch directory the evaluator uses, lists its available tools, and reports the worktree's path and the exact files it wrote.
3. Both report, within 10 minutes. On Claude Code, arm a deadline wake before each probe wait (a background `sleep 540` with `timeout: 600000`, the heartbeat's form), since nothing else wakes an ended turn before a worker launches. Record its task ID and the probe wait it belongs to; keep only one deadline timer active. If that matching wake arrives before the awaited report, the deadline is missed. When the report arrives first, stop that timer and retire its ID before starting another wait or launching workers. Ignore a late notification from a retired timer; it cannot fail a later wait. Then **Continue** the finished probe coordinator once and require a fresh final message, within another 10 minutes (a missed deadline is a preflight failure): after a merge, `team` depends on resuming a finished worker. Then verify both probes are completed and their owned resources cleaned up before any change starts, closing only on a legacy backend that requires it. Any failure, a missing tool, or **a permission prompt surfacing during the probe** stops the run: normal work was not proven available unattended, whether the host rejected the request immediately or left a verified prompt waiting. Do not infer either behavior on an unverified host. A successful role spawn also proves nesting depth on the installed version (some versions defaulted to one layer). On Claude Code the probe role's spawn may return before its report, which then arrives as a notification (Headless sessions in `dev`'s host-adapters reference): exercise the adapter’s interim-yield path in that case. The supervisor treats the interim waiting message as still working under the same probe deadline; only the resumed final report satisfies the probe. This passes only when the role’s notification resumes the coordinator and its final report comes after the role’s report.

**Unproven until first use, and named in the run's report:** creating and updating a PR, tracker writes, and merge rights under branch rules. No check exists for them that doesn't perform them.

## Codex lifecycle probe

Before launching changes, prove these operations with disposable agents that write no project files (the permissions probe above separately proves filesystem access):

1. Complete one native agent and resume it with `followup_task`; require a fresh report.
2. Start a disposable active wait, observe it running, interrupt it with the supplied stop operation, and verify its terminal status through the host adapter. Confirm any process it launched stopped too; a tool interruption alone does not prove process cleanup. When the supplied stop operation preserves the context (`interrupt_agent`), resume that interrupted context once and require a fresh report to prove intentional continuation. A legacy close may destroy the context: do not resume a closed agent; step 1 proves continuation before closure instead.
3. In a probe coordinator, sequentially spawn and await four distinct short roles, without closing completed contexts on the current interface. Record every ID and completion. This tests nested delegation and capacity reuse across more retained contexts than the usual active-work budget. Use legacy closes only if the supplied backend requires them.

A missing operation, a nonterminal status, an unknown descendant or a queued role that cannot finish within the existing probe deadline fails preflight; stop and verify all known probe agents and resources before releasing the lock. Capacity reuse never proves a running worker stopped, and completed contexts must not be restarted except by the recorded Continue operation.
